# 시사경제용어사전 — 웹 파일럿

엑셀 원본(3,029개 용어)을 그대로 쓰는 사전 + 4지선다 퀴즈 + 오답 복습 앱이다.

## 실행

**윈도우** — `econ-dict.vbs`를 더블클릭한다. 콘솔 창 없이 기본 브라우저로 앱이 열린다.
우클릭 → 바로 가기 만들기로 바탕화면에 두고 써도 된다.

보안 정책 등으로 VBScript가 막혀 있으면 `econ-dict-fallback.bat`을 대신 쓴다.
동작은 같고, 실행 순간 콘솔 창이 잠깐 깜빡인다.

**그 외** — `index.html`을 브라우저에서 직접 연다.

서버는 필요 없다. 데이터셋을 `fetch`가 아니라 `data/terms.js`의 전역 변수
(`window.TERMS`)로 넘기기 때문에 `file://`에서도 동작한다.

## 파일 구조

```
econ-dict/
├─ econ-dict.vbs       윈도우 런처 (콘솔 창 없이 index.html 을 연다)
├─ econ-dict-fallback.bat  VBScript 가 막힌 환경용 대체 런처
├─ index.html          화면 뼈대 (앱바 / 4개 탭 / 상세 시트)
├─ css/style.css       라이트·다크 테마, 모바일 우선 레이아웃
├─ js/
│  ├─ storage.js       localStorage 읽기·쓰기 계층 (오답·즐겨찾기·통계·테마)
│  ├─ dictionary.js    데이터 적재, 초성/알파벳 색인, 검색, 목록 렌더, 상세 시트
│  ├─ quiz.js          4지선다 출제 엔진, 정답 마스킹, 채점, 결과
│  └─ app.js           탭 라우팅, 오답노트 화면, 통계 화면, 부트스트랩
└─ data/
   ├─ terms.js         앱이 읽는 데이터셋 (window.TERMS)
   └─ terms.json       같은 데이터의 JSON 원본 (안드로이드 이식용)
```

## 데이터 스키마

```json
{ "id": 1, "topic": "사회", "term": "0.5인 가구", "initial": "0-9", "def": "…" }
```

- `topic` — 금융 815 / 경제 705 / 경영 631 / 공공 556 / 과학 210 / 사회 112
- `initial` — 정렬·색인 키. 한글은 초성(된소리는 예사소리로 통합), 영문은 대문자, 숫자는 `0-9`

## 기능

**사전** — 용어·설명 전문 검색(하이라이트), 주제 필터, 가나다·ABC순 / 주제별 / 즐겨찾기
정렬, 초성·알파벳 색인, 60개 단위 무한 스크롤, 상세 시트에서 즐겨찾기 지정.

**퀴즈** — 범위(전체·주제·즐겨찾기·오답노트) × 유형(설명→용어 / 용어→설명 / 혼합) ×
문항 수(5·10·20·30). 오답 보기는 같은 주제에서 뽑아 난도를 유지한다. 설명 안에 정답
용어가 나오면 `○○○`로 가린다(괄호 병기 형태까지 처리, 미탐지율 약 1%). 키보드 1~4 선택,
Enter로 다음 문항.

**오답노트** — 틀린 용어를 오답 횟수·마지막 시각과 함께 저장한다. 복습 퀴즈에서 연속 2회
맞히면 자동 졸업되고 목록에서 빠진다. 다시 틀리면 연속 기록은 0으로 돌아간다.

**통계** — 누적 문항·정답률·연속 학습일·주제별 정답률. 학습기록 JSON 내보내기와 초기화.

## 저장 위치

모든 학습 기록은 브라우저 `localStorage`의 `econdict.v1` 키 하나에 들어간다.
브라우저 데이터를 지우면 함께 사라진다. 시크릿 모드 등 저장이 막힌 환경에서도
앱 자체는 정상 동작한다(기록만 남지 않음).

## 안드로이드 이식 시 유의점

- `js/storage.js`의 함수 시그니처(`isFav` / `toggleFav` / `markWrong` / `markCorrect` /
  `recordAnswer` / `stats` …)만 유지한 채 내부를 Room·DataStore 호출로 바꾸면 나머지
  로직은 그대로 쓸 수 있다.
- 2.6MB짜리 `terms.js`를 통째로 메모리에 올리는 방식은 파일럿 한정이다. 네이티브로 갈
  때는 `terms.json`을 빌드 시점에 SQLite(Room)로 넣고 FTS4/FTS5 인덱스를 걸어
  검색·정렬을 DB에 맡기는 편이 낫다.
